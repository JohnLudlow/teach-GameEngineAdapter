Lesson 8: Selection Lifecycle Baseline

Make selection ownership, invalid state, empty controls, and removal recovery explicit.

Mission connection: The future adapter must not silently choose application state. These rules keep selection owned by the consumer while making interaction deterministic when a collection changes.

The consumer owns initial selection

Every non-empty list and tab control receives its initial selection from the consumer. The control definition is invalid if that selection is missing or does not identify a current item or page. The adapter must reject invalid state rather than silently selecting a different item.

Control state at creation Required result Why it matters
Non-empty control with a valid supplied selection Render with that item or page selected. The consumer remains the source of truth.
Non-empty control with no supplied selection Reject the control definition as invalid. The adapter does not invent an application choice.
Non-empty control with an unknown supplied identifier Reject the control definition as invalid. The visible selection cannot disagree with the current collection.

Empty controls are visible but non-interactive

An empty list or tab control still renders, but it has no selection. Navigation and activation do nothing. This is different from hiding the control: the consumer may still need its layout position or empty-state appearance.

Focus boundary: an empty control has no eligible item or page to activate. Its precise relationship to parent focus traversal must be represented by the future control-tree contract; this lesson only establishes that its own navigation and activation do nothing.

Recovering after selected-item removal

When the selected item or page is removed, select the next remaining element. If the removed element was last, select the previous remaining element. If removal leaves the collection empty, the control follows the non-interactive empty-control rule.

Given: list [A, B, C] with B selected
When: B is removed
Then: C is selected

Given: tabs [Map, Economy, Research] with Research selected
When: Research is removed
Then: Economy is selected

Given: list [A] with A selected
When: A is removed
Then: the list is empty and non-interactive

Report transitions back to the consumer

Selection can change through arrow keys, tab navigation, click selection, or removal recovery. After any change, the control must report the selected identifier to the consumer. That lets the game or application update its state without the adapter taking ownership of domain data.

Retrieval practice

Answer each question from memory, then expand it to check your answer.

Who supplies the initial selection for a non-empty list or tab control?

The consumer supplies it. The adapter validates that the identifier exists in the current items or pages.

What happens when an initial selection is missing or invalid?

The control definition is rejected as invalid; the adapter does not silently select a fallback.

What happens when the selected item is removed and a next item exists?

The next remaining item becomes selected. If none exists, the previous remaining item becomes selected.

What can an empty list or tab control do?

It renders as non-interactive. Navigation and activation do nothing because it has no selected item or page.
