Lesson 7: Navigation Bounds Baseline

Make list and tab navigation deterministic at the beginning and end of their collections.

Mission connection: “Unpredictable” interaction often hides at collection boundaries. These rules turn list and tab navigation into precise behavior that a headless test can prove before a terminal library is selected.

Two controls, deliberately different rules

Lists clamp their selection at the first and last item. Tab controls wrap their selected page from one end to the other. The difference is intentional and must be represented by the control’s behavior, not inferred from a generic navigation helper.

Control Input at first item/page Input at last item/page
List Up keeps the first item selected. Down keeps the last item selected.
Tab control Left selects the last tab. Right selects the first tab.

Clamping versus wrapping

Clamping keeps the current selection when navigation would move beyond the collection. Wrapping moves selection from one edge to the opposite edge. Both are valid behaviors; the important requirement is that each control specifies one rather than leaving its edge behavior to a library default.

List: selected index 0 of 3
Input: Up
Result: selected index 0

Tab control: selected index 2 of 3
Input: Right
Result: selected index 0

What these rules do not decide

This baseline only covers navigation when an item or page is already selected. It does not define the initial selection, behavior for empty controls, or recovery when the selected item or page is removed. Those need explicit requirements before implementation.

Testing rule: a test should assert the selected identifier or index after an input sequence. It should not merely assert that an arrow key was received, because that does not prove the collection-boundary behavior.

Worked test scenarios

Given: a list contains [A, B, C] and A is selected
When: Up is pressed
Then: A remains selected

Given: tabs contain [Map, Economy, Research] and Research is selected
When: Right is pressed
Then: Map is selected

Retrieval practice

Answer each question from memory, then expand it to check your answer.

What happens when Up is pressed while the first list item is selected?

The selection remains on the first item. List navigation clamps at both bounds.

What happens when Right is pressed while the last tab is selected?

The first tab becomes selected. Tab navigation wraps at both bounds.

Why should list and tab bounds not be left to a shared helper’s default?

They intentionally have different requirements: lists clamp and tab controls wrap. A default could silently apply the wrong behavior.

What selection behavior remains undecided after this lesson?

Initial selection, empty-control behavior, and recovery after a selected item or page is removed remain open.
